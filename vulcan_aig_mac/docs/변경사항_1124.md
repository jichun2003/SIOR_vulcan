# 변경사항 (2026-11-24)

증상: 양자화 모델을 보드에 올리자 2 m는 잡히는데 3.6 m에서 거의 못 잡음, 기록상 검출 0%.
결론: 모델(양자화)은 거의 정상이었다. 문제는 보드 앱이 모델과 주고받는 부분 3곳에 있었다.
세 가지 모두 원본(aaa_code_aig)에도 있던 문제이며, 원본은 이 보드에서 빌드·실행된 적이 없어 드러나지 않았다
(PC stub 시험은 항상 conf 0.87 가짜 검출을 내므로 값이 틀려도 통과한다).

## 결과 (3.6 m, 흰 벽 앞 고정 과녁)

| | 수정 전 | 수정 후 |
|---|---|---|
| NPU 검출률 | 약 15% (들쭉날쭉) | 94~100% |
| 앱이 표적으로 채택 | 0% | 94~100% |
| 평균 conf | 약 0.44 | 약 0.6 |
| 빈 화면 오검출 | - | 0 |

같은 사진 비교: fp(원본 모델) 0.85, PC int8 시뮬레이터 약 0.67, 보드 int8 약 0.6.
양자화 손실은 0.2 정도로 전시에 문제없는 수준.

## 문제 1. 입력 값 범위 (가장 큰 원인) — board_app/npu_vision.c

- NPU(int8)는 입력 바이트를 부호 있는 정수(-128~127)로 그대로 읽는다.
  모델 약속: 입력 = round(밝기/255 x 128) → 0~127 (정규화 + 입력 양자화).
- 앱은 카메라 밝기 0~255를 그대로 넣었다 → 128 이상(밝은 픽셀)이 음수로 뒤집힘.
  흰색 255 → -1(거의 검정), 밝은 회색 200 → -56. 흰 벽 배경이 망가져 먼 표적일수록 실패.
- 수정: 256칸 변환표(in_lut)로 0~255 → 0~127 변환 후 NPU에 넣는다 (127 상한 clamp).
  환경변수 AIG_IN_MODE=half(기본)/raw/s128 로 비교 가능 (진단용).
- 미리보기 영상은 변환을 거치지 않는다 (자연 밝기 그대로).

## 문제 2. 클래스 번호 — board_app/aig_config.h

- SDK 검출 후처리는 SSD 관례대로 0번을 "배경"으로 비워 두고 표적을 1번으로 준다.
- 앱은 target_class = 0 → 모든 검출을 버림. 로그: "표적 없음 (탐지 1개)".
- 수정: target_class = -1 (클래스 무시, 단일 클래스 모델).

## 문제 3. 카메라 점유 ("버퍼 크기 협상 실패")

- 카메라는 한 번에 한 프로그램만 쓸 수 있다. 이전 aig_turret이 남아 있으면 새 앱은
  "CameraSetConfig(1280x720) 실패"로 죽는다 (커널: vb2_is_busy, REQBUFS busy).
- 수정: run.sh / conf_watch.sh가 시작 시 남은 aig_turret을 정리.
  conf_watch.sh의 DUR=초 는 앱 자체에 timeout -s INT를 걸어 정상 종료시킨다.

## 그 밖의 변경

- aig_config.h: conf_threshold 0.4 → 0.3 (NPU 후처리 문턱과 동일, 빈 화면 오검출 0 확인)
- 카메라 색 순서: BGRX 유지 (프레임 통계로 확인. XRGB는 파랑 자리에 빈 바이트 255가 들어감)
- 11/20 수정분 포함: CPU 리사이즈(AIG_SW_RESIZE), 카메라 RGB32(4바이트) 처리,
  카메라 1초 타임아웃 + 3초 끊기면 exit 3 (camera_api.c, main.c)
- conf_watch.sh 추가: 미리보기 없이 1초마다 검출률·conf 요약 (발열 적음)
- pc_tools/: grab_frames.py(보드 프레임 저장), eval_csi_int8.py(PC fp/int8 비교)
